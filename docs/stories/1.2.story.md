## Status

## Story

**As a** developer,
**I want** the core database schema implemented with TypeORM,
**so that** I can store and retrieve schedule, coach, and user data.

## Acceptance Criteria

1. TypeORM entities define models: User, Coach, TrainingType, ScheduleEntry, Reminder, ClubInfo, AdminUser
2. User entity includes Telegram ID, preferences (reminder minutes), created/updated timestamps
3. Coach entity includes name, bio, photo URL, specializations, certifications, active status
4. TrainingType entity includes name, description, difficulty, impact types, equipment
5. ScheduleEntry entity includes training type, coach, datetime, duration, status (scheduled/cancelled)
6. Reminder entity links User to ScheduleEntry with notification status
7. ClubInfo entity stores club details as a singleton
8. AdminUser entity stores admin credentials with password hash
9. TypeORM migrations run successfully and seed script creates test data
10. Database connection tested via existing health check endpoint

```typescript
// User
interface User {
    id: string; // UUID
    telegramId: number; // BIGINT
    firstName: string;
    lastName: string | null;
    username: string | null;
    reminderMinutes: number; // default: 30
    createdAt: Date;
    updatedAt: Date;
}

// Coach
interface Coach {
    id: string;
    name: string;
    bio: string | null;
    photoUrl: string | null;
    specializations: string[]; // TEXT[]
    certifications: string[]; // TEXT[]
    isActive: boolean; // default: true
    createdAt: Date;
    updatedAt: Date;
}

// TrainingType
interface TrainingType {
    id: string;
    name: string;
    description: string | null;
    difficulty: 'beginner' | 'intermediate' | 'advanced';
    impactTypes: ('cardio' | 'strength' | 'flexibility' | 'balance')[];
    equipment: string[];
    isActive: boolean;
    createdAt: Date;
    updatedAt: Date;
}

// ScheduleEntry
interface ScheduleEntry {
    id: string;
    trainingTypeId: string;
    coachId: string;
    startTime: Date;
    durationMinutes: number;
    status: 'scheduled' | 'cancelled';
    cancellationReason: string | null;
    createdAt: Date;
    updatedAt: Date;
}

// Reminder
interface Reminder {
    id: string;
    userId: string;
    scheduleEntryId: string;
    notifyAt: Date;
    status: 'pending' | 'sent' | 'failed';
    sentAt: Date | null;
    createdAt: Date;
}

// ClubInfo (singleton)
interface ClubInfo {
    id: string;
    name: string;
    address: string;
    phone: string;
    workingHours: Record<string, { open: string; close: string } | null>;
    latitude: number | null;
    longitude: number | null;
    logoUrl: string | null;
    updatedAt: Date;
}

// AdminUser
interface AdminUser {
    id: string;
    email: string;
    passwordHash: string;
    name: string;
    isActive: boolean;
    lastLoginAt: Date | null;
    createdAt: Date;
    updatedAt: Date;
}
```

### Database Schema SQL Reference
[Source: architecture.md#Section-9.1]

**Required Tables:**
- `users` - UUID PK, BIGINT telegram_id UNIQUE, reminder_minutes default 30
- `coaches` - UUID PK, specializations/certifications as TEXT[], is_active default true
- `training_types` - UUID PK, difficulty CHECK constraint, impact_types/equipment as TEXT[]
- `schedule_entries` - UUID PK, FKs to training_types and coaches, status CHECK constraint
- `reminders` - UUID PK, FKs with CASCADE delete, UNIQUE(user_id, schedule_entry_id)
- `club_info` - UUID PK, working_hours as JSONB
- `admin_users` - UUID PK, email UNIQUE, password_hash for bcrypt

**Required Indexes:**
[Source: architecture.md#Section-9.2]
```sql
-- Schedule queries
CREATE INDEX idx_schedule_start_time ON schedule_entries(start_time);
CREATE INDEX idx_schedule_coach ON schedule_entries(coach_id);
CREATE INDEX idx_schedule_type ON schedule_entries(training_type_id);
CREATE INDEX idx_schedule_status ON schedule_entries(status);

-- Reminder processing
CREATE INDEX idx_reminders_notify_at ON reminders(notify_at) WHERE status = 'pending';
CREATE INDEX idx_reminders_user ON reminders(user_id);

-- User lookup
CREATE INDEX idx_users_telegram_id ON users(telegram_id);
```

### TypeORM Entity Patterns
Use TypeORM decorators:
- `@Entity()` for table mapping
- `@PrimaryGeneratedColumn('uuid')` for UUID primary keys
- `@Column()` with appropriate types
- `@CreateDateColumn()` and `@UpdateDateColumn()` for timestamps
- `@ManyToOne()` and `@OneToMany()` for relations
- `@Index()` for database indexes
- `@Unique()` for unique constraints
