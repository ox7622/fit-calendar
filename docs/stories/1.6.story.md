## Dev Notes

### Required GitHub Secrets

Add these in **GitHub → Repository Settings → Secrets and variables → Actions**:

| Secret | Value |
|--------|-------|
| `STAGING_HOST` | VPS IP or hostname (e.g. `1.2.3.4`) |
| `STAGING_USER` | SSH user on VPS (e.g. `deploy`) |
| `STAGING_SSH_KEY` | Private SSH key (PEM format, VPS must have matching public key in `~/.ssh/authorized_keys`) |
| `STAGING_WORK_DIR` | Absolute path on VPS (e.g. `/opt/fitcalendar`) |

`GITHUB_TOKEN` is **automatically provided** by GitHub Actions — no manual setup needed for ghcr.io.

### VPS Manual Setup Steps

These steps must be performed once on the staging VPS before the CD workflow can succeed:

1. **Install Docker and Docker Compose plugin:**
   ```bash
   curl -fsSL https://get.docker.com | sh
   apt-get install -y docker-compose-plugin
   ```

2. **Create app directory:**
   ```bash
   mkdir -p /opt/fitcalendar
   ```

3. **Create SSH deploy user (optional but recommended):**
   ```bash
   adduser --disabled-password deploy
   mkdir -p /home/deploy/.ssh
   echo "<your-public-key>" >> /home/deploy/.ssh/authorized_keys
   chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
   usermod -aG docker deploy
   ```

4. **Copy staging Docker Compose file to VPS:**
   ```bash
   scp docker/docker-compose.staging.yml deploy@<VPS_IP>:/opt/fitcalendar/
   ```

5. **Create `.env.local` on VPS:**
   ```bash
   # /opt/fitcalendar/.env.local
   NX_DB_HOST=postgres
   NX_DB_PORT=5432
   NX_DB_NAME=fitcalendar
   NX_DB_USER=fitcalendar
   NX_DB_PASS=<strong-password>
   TELEGRAM_BOT_TOKEN=<token>
   TELEGRAM_WEBHOOK_SECRET=<secret>
   TELEGRAM_WEBHOOK_URL=https://<domain>/webhook
   MINI_APP_URL=https://<domain>/mini-app
   ```

6. **Enable branch protection rules** in GitHub → Settings → Branches:
   - Protect `main` and `develop`
   - Require status checks: `ci` to pass before merging

### Workflow Architecture

```
Push / PR
    │
    └─► CI Workflow (.github/workflows/ci.yml)
            ├── pnpm install (cached)
            ├── nx-set-shas (compute affected base/head)
            ├── nx affected -t lint
            ├── nx affected -t typecheck
            ├── nx affected -t test
            ├── nx affected -t build
            └── docker build --no-push (api/bot only if affected)

Manual Trigger
    │
    └─► CD Workflow (.github/workflows/cd.yml)
            ├── pnpm install
            ├── nx build api bot
            ├── docker login ghcr.io
            ├── docker build + push api (latest + SHA)
            ├── docker build + push bot (latest + SHA)
            └── SSH to VPS
                    ├── docker compose pull
                    ├── docker compose up -d --remove-orphans
                    └── (optional) run migrations
```

### Caching Strategy

| Cache | Key | Restores |
|-------|-----|----------|
| pnpm store | `pnpm-lock.yaml` hash | `~/.pnpm-store` (via `actions/setup-node cache: pnpm`) |
| Nx computation | `pnpm-lock.yaml` hash | `.nx/cache` directory |

### Nx Affected Logic

`nrwl/nx-set-shas@v4` sets:
- `NX_BASE`: last successful CI commit on this branch (or `main` for new branches)
- `NX_HEAD`: current `HEAD`

This allows `nx affected` to skip projects with no changes, keeping CI fast.

### Image Naming Convention

```
ghcr.io/<github_owner>/fit-calendar-api:latest
ghcr.io/<github_owner>/fit-calendar-api:<git-sha>
ghcr.io/<github_owner>/fit-calendar-bot:latest
ghcr.io/<github_owner>/fit-calendar-bot:<git-sha>
```
