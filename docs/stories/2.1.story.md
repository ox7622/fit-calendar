# Story 2.1: Schedule API Endpoints

## Status

Complete

## Story

**As a** mini-app user,
**I want** the API to serve schedule data,
**so that** I can see today's and the week's fitness classes.

## Acceptance Criteria

1. `GET /schedule/today` returns an array of `ClassResponseDto` for today
2. `GET /schedule/week` returns `WeekScheduleDto` with 7 days starting from today (inclusive)
3. `GET /schedule/:date` returns classes for a specific `YYYY-MM-DD` date
4. All endpoints are protected by `TelegramAuthGuard`
5. `includeCancelled=false` (default) filters out cancelled classes
6. `includeCancelled=true` includes cancelled classes
7. Caching — out of scope for this sprint

## Dev Notes

-   `ScheduleEntry.startTime` is `TIMESTAMPTZ` — date range queries use UTC start/end of day
-   `endTime` is computed as `startTime + durationMinutes * 60 * 1000`
-   `getWeek()` uses date-fns `addDays(startOfDay(new Date()), i)` for i=0..6
-   Classes are grouped by `format(date, 'yyyy-MM-dd')`
-   Caching (AC 7) is out of scope for Sprint 2
