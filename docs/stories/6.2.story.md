# Story 6.2: Schedule Management - View & List

## Status

ready-for-dev

## Story

**As a** club administrator,
**I want** to view all scheduled classes in a list or calendar format,
**so that** I can see the current schedule at a glance.

## Acceptance Criteria

1. `GET /api/v1/admin/schedule` returns a paginated list of schedule entries with `{ items, total, page, pageSize }`.
2. Query params: `from` (ISO date, default = start of current week), `to` (ISO date, default = +14 days), `coachId?`, `trainingTypeId?`, `status?` (`scheduled` | `cancelled` | `all`, default `all`), `page?` (default 1), `pageSize?` (default 50, max 200).
3. Response items include nested `coach` (id, name, photoUrl) and `trainingType` (id, name, difficulty) — no extra round-trips needed for the list UI.
4. Endpoint is protected by `AdminAuthGuard` from Story 6.1.
5. Admin Dashboard at `/admin/dashboard` shows the upcoming-week schedule by default.
6. Toggle between **List view** (chronological table) and **Calendar view** (weekly grid: 7 columns × time-of-day rows).
7. Each entry shows class name, date/time, coach name, status. Cancelled entries are visually distinguished (strikethrough class name + red `Отменено` badge).
8. "Previous week" / "Next week" navigation arrows update the date range and re-fetch.
9. Filter dropdowns: coach, training type, status. Multi-filters combine with AND.
10. Tapping/clicking an entry navigates to its edit page (`/admin/schedule/:id` — implemented in Story 6.3); for now, navigation just stub-routes there.

## Dev Notes

### Read-only story

This story is purely a viewer. No mutations. That keeps it scoped — combine it with Stories 6.3/6.4 in a single dev sprint if you have the bandwidth.

### Why pagination at this scale

Even in a single-club MVP, the admin's "all schedule entries" view will hold months of historical data. 50 per page with `total` for the UI is enough — no infinite scroll.

### Calendar view simplification

Don't reach for a calendar lib (FullCalendar, react-big-calendar). The admin schedule fits a simple 7-column CSS grid. If the dev finds themselves needing drag-and-drop, time-zone handling beyond the club's local time, or recurrence rendering, **stop and raise it** — that's a Phase 2 feature.

### Endpoint contract

**`GET /api/v1/admin/schedule`** with the query params from AC2 → 200:

```json
{
    "items": [
        {
            "id": "uuid",
            "startTime": "2026-05-04T08:00:00.000Z",
            "durationMinutes": 60,
            "status": "scheduled",
            "cancellationReason": null,
            "trainingType": { "id": "uuid", "name": "Йога", "difficulty": "beginner" },
            "coach": { "id": "uuid", "name": "Мария Иванова", "photoUrl": "https://..." }
        }
    ],
    "total": 42,
    "page": 1,
    "pageSize": 50
}
```
