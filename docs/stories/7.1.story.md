# Story 7.1: Membership Plan Catalog

## Status

ready-for-dev

## Story

**As a** club administrator,
**I want** to define the club's membership plans (12-month, 6-month, drop-in, etc.) with their durations, prices, and included features,
**so that** customers can be assigned to plans and members can see what plans the club offers.

**As a** Mini App user,
**I want** to see all available membership plans with their features and prices,
**so that** I can decide which plan to choose when I'm at the club next.

## Acceptance Criteria

1. New entity `MembershipPlan` stored in PostgreSQL with: id, name, durationValue, durationUnit (`day | week | month`), priceRub, features (free-form `string[]`), guestVisitsAllowed (int, default 0), freezeDaysAllowed (int, default 0), isActive, createdAt, updatedAt.
2. `GET /api/v1/membership-plans` returns all **active** plans, sorted by durationValue ASC within unit, then unit ascending (day → week → month). Public endpoint (no admin auth, no telegram auth — this is brochure information).
3. `GET /api/v1/admin/membership-plans` returns all plans (active + inactive) sorted by name. Protected by `AdminAuthGuard`.
4. `GET /api/v1/admin/membership-plans/options` returns active plans as `{ id, name, durationLabel }[]` for assignment dropdowns (used by Story 7.4). Protected.
5. `POST /api/v1/admin/membership-plans` creates a plan. Body: `{ name, durationValue, durationUnit, priceRub, features, guestVisitsAllowed, freezeDaysAllowed, isActive? }`.
6. `PUT /api/v1/admin/membership-plans/:id` updates a plan. **Edits do NOT propagate to existing customer memberships** — counter values on existing memberships are frozen at the time of assignment.
7. Hard delete (`DELETE /api/v1/admin/membership-plans/:id`) is allowed only when zero memberships reference this plan. Otherwise 409 with `"План не может быть удалён: есть активные подписки. Используйте деактивацию."`
8. Mini App: new public page at `/plans` showing all active plans as cards (name, duration label, price, features list, guest visits / freeze days as separate badges).
9. Plans page accessible from the Mini App profile area (Story 7.4) AND from the Mini App's club info page as a "Доступные абонементы" link.
10. Admin UI at `/admin/plans` lists all plans, "Add Plan" button, edit page for each.

## Dev Notes

### Why this is safer to build before customer/membership work

7.1 is **read-mostly admin CRUD on a brand-new entity** with no foreign-key dependencies (no membership table yet). It can ship before 7.2 (customer refactor) without touching anything that exists today. Use this story to establish the Epic 7 patterns (admin route shape, mini-app design tokens for plan cards) before doing the riskier auth refactor.

### Why `priceRub` is an `int`, not decimal

Russian prices are typically whole rubles. Storing as int avoids float drift and keeps display formatting simple. If the club ever wants kopecks, switch to int storing kopecks (~1/100 ruble) — never use float for money.

### Why edits don't propagate to existing memberships (AC6)

If admin edits the 12-month plan from "2 guest visits" to "3 guest visits," existing members of that plan stay at 2. Otherwise an admin retroactively gives all current members an extra perk — and members who already used their 2 visits would suddenly have 1 left. The membership entity (Story 7.4) snapshots `guestVisitsRemaining` at assignment time. Plan edits affect _future_ memberships only.

### Duration formatting helper

`formatDuration(value, unit)` produces Russian labels:

-   `(1, 'day')` → `"1 день"`
-   `(7, 'day')` → `"7 дней"` (note: pluralization rules)
-   `(1, 'week')` → `"1 неделя"`
-   `(2, 'week')` → `"2 недели"`
-   `(1, 'month')` → `"1 месяц"`
-   `(12, 'month')` → `"12 месяцев"`

Russian pluralization is non-trivial. Use a small helper, **not** a library:

```typescript
function pluralize(value: number, [one, few, many]: [string, string, string]): string {
    const mod10 = value % 10;
    const mod100 = value % 100;
    if (mod10 === 1 && mod100 !== 11) return one;
    if (mod10 >= 2 && mod10 <= 4 && (mod100 < 10 || mod100 >= 20)) return few;
    return many;
}

const DAY_FORMS: [string, string, string] = ['день', 'дня', 'дней'];
const WEEK_FORMS: [string, string, string] = ['неделя', 'недели', 'недель'];
const MONTH_FORMS: [string, string, string] = ['месяц', 'месяца', 'месяцев'];
```

Place in `apps/mini-app/src/shared/utils/formatRussian.ts` and re-export. This same helper is used by Story 7.4 for "осталось N дней" countdown, and `intl` Russian formatters can't handle these word forms directly.

### Endpoint contracts

**`GET /api/v1/membership-plans`** → `200`:

```json
[
    {
        "id": "uuid",
        "name": "12-месячный",
        "durationValue": 12,
        "durationUnit": "month",
        "priceRub": 30000,
        "features": ["2 гостевых визита", "1 месяц заморозки"],
        "guestVisitsAllowed": 2,
        "freezeDaysAllowed": 30
    }
]
```

Note: `isActive` not exposed publicly (filtered server-side). `createdAt`/`updatedAt` not exposed publicly. Admin endpoint includes those.
