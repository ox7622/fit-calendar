# Массовые действия в расписании (admin) — дизайн

**Дата:** 2026-06-10
**Статус:** утверждён (ожидает финального ревью спеки)

## Цель

Дать админу три массовых действия в календаре расписания, чтобы не заводить
занятия по одному:

1. **Скопировать всю неделю** — все занятия текущей недели на любую выбранную неделю.
2. **Скопировать занятие** — одно занятие целиком на одну или несколько дат.
3. **Повторяющиеся занятия** — создать по правилу «дни недели + время», например
   каждый Пн/Ср/Пт в 18:30, на заданный горизонт.

## Принятые решения (рамки)

- **Модель — пачка независимых занятий.** Никаких «серий»/RRULE в БД. Каждое
  созданное занятие — обычная строка `schedule_entries`, дальше редактируется и
  отменяется по отдельности существующими эндпоинтами. **Миграции не нужны.**
- **Дубли разрешены.** Если на целевое время уже есть занятие — создаём всё равно,
  без проверки пересечений.
- **Горизонт повторов — два режима:** диапазон дат (`с` — `по`) **или** «N недель вперёд».
- **Копия недели — на любую выбранную неделю** (одна целевая неделя за раз).
- **Копируются только активные (`scheduled`) занятия;** отменённые (`cancelled`) пропускаются.
- **Превью с количеством** перед созданием («Будет создано N занятий») — лёгкая страховка,
  раз дубли не проверяем.
- **Лимит пачки — 200 занятий** за одну операцию (защита от случайного гигантского запроса).
- **Подсветка наложений в календаре.** Раз дубли не блокируем — глаз видит их сам:
  занятия с **одинаковыми датой и временем начала** (2+ в одном слоте) получают
  **красную обводку**. Считаются только активные (`scheduled`) занятия; отменённые
  не участвуют. Чисто фронтовое — бэкенд не трогаем.

### Вне рамок (YAGNI)
- Связанные серии и «изменить/отменить все сразу».
- Проверка дублей / пересечений по тренеру или залу.
- Серверная дата-логика повторов (её делает фронт — см. ниже).

## Архитектура

**Фронт считает даты → один бэкенд-эндпоинт массово создаёт.** Согласовано с тем, как
фронт уже формирует `startTime` для обычного создания. Дата-логика — чистые тестируемые
функции; бэкенд остаётся «тупым» bulk-insert'ом.

### Бэкенд — 1 новый эндпоинт

`POST /admin/schedule/bulk` (под `AdminAuthGuard`, как остальные admin-роуты).

**DTO** `BulkCreateScheduleDto`:
```
entries: CreateScheduleEntryDto[]   // @ValidateNested({each:true}) + @Type
                                    // @ArrayNotEmpty, @ArrayMaxSize(200)
```
`CreateScheduleEntryDto` переиспользуем как есть (`trainingTypeId`, `coachId`,
`startTime: Date`, `durationMinutes ∈ {30,45,60,90}`).

**Сервис** `AdminScheduleService.bulkCreate(dto)`:
1. Собрать уникальные `coachId` и `trainingTypeId` из всех `entries`.
2. Проверить активность каждого уникального тренера и типа (переиспользовать
   `assertActiveCoach` / `assertActiveTrainingType`). Если хоть один неактивен —
   `BadRequestException` с понятным русским сообщением; **ничего не создаётся**.
3. Вставить все занятия `status='scheduled'` **одной транзакцией**
   (`dataSource.transaction` → `manager.save(ScheduleEntry, rows)`).
4. Вернуть `{ created: number; items: AdminScheduleItemDto[] }` (перезагрузить с
   `coach`/`trainingType` для маппинга через `toAdminScheduleItem`).

Без напоминаний и событий (как и обычный `create`).

**Контроллер** — метод рядом с `create`:
```
@Post('bulk')
@HttpCode(HttpStatus.CREATED)
bulkCreate(@Body() dto: BulkCreateScheduleDto): Promise<BulkCreateResponseDto>
```

### Фронт — чистые функции (юнит-тесты)

Модуль `apps/admin/src/features/schedule/bulk/` (чистые функции на `date-fns`,
неделя с понедельника — `weekStartsOn: 1`, как везде):

- `buildRecurrence(params): IScheduleFormPayload[]`
  params: `{ trainingTypeId, coachId, durationMinutes, time:"HH:mm", weekdays:number[], range }`,
  где `range = { mode:'dates', from, to } | { mode:'weeks', from, weeks }`.
  Для каждого дня в горизонте, если его день недели ∈ `weekdays`, собрать `startTime`
  из даты + `time`.
- `buildWeekCopy(items, sourceWeekStart, targetWeekStart): IScheduleFormPayload[]`
  Только `status==='scheduled'`. Каждое занятие сдвигается на разницу недель
  (целое число недель), сохраняя день недели и время.
- `buildDuplicate(item, targetDates: Date[]): IScheduleFormPayload[]`
  Копия одного занятия на каждую целевую дату (время берётся из исходного либо
  переопределяется в модалке).

### Фронт — API-клиент

`adminScheduleApi.bulkCreate(entries: IScheduleFormPayload[]): Promise<{ created:number; items:IAdminScheduleItem[] }>`
→ `POST /admin/schedule/bulk`.

### Фронт — UI

- **Тулбар календаря расписания:** кнопки «Копировать неделю» и «Повторяющееся занятие».
- **Действие на занятии** (карточка в календаре и/или страница редактирования):
  «Копировать».
- **Модалки** (общий компонент превью внизу каждой):
  - *Повтор:* тип занятия, тренер, длительность, время, чекбоксы дней недели,
    переключатель режима (диапазон дат / N недель) + соответствующие поля.
  - *Копия недели:* выбор целевой недели (date-picker по понедельникам).
  - *Копия занятия:* выбор одной или нескольких целевых дат + (опц.) время.
  - **Превью:** «Будет создано N занятий», список дат/времени, кнопки «Создать» / «Отмена».
    Пустой результат (N=0) — кнопка «Создать» заблокирована.

После успешного `bulkCreate` — перезагрузить список календаря и показать тост
«Создано N занятий».

- **Подсветка наложений** в `ScheduleCalendar.tsx`: чистый хелпер
  `findOverlappingIds(items): Set<string>` — группирует активные занятия по
  `(дата + время старта)`, возвращает id из групп размером ≥ 2. Эти кнопки получают
  красную обводку (`ring`/`border` ошибки), отличную от стиля отменённых (line-through).

## Обработка ошибок

- Пустой `entries` или > 200 → 400 (валидация DTO), фронт также не даёт отправить.
- Неактивный тренер/тип среди занятий → 400 с сообщением, **атомарно ничего не создаётся**.
- Сетевая ошибка → тост с ошибкой, занятия не создаются (транзакция).

## Тестирование

- **Бэкенд (jest):** `bulkCreate` — успешная пачка; отказ при неактивном тренере/типе
  (ничего не создано); лимит 200; пустой массив.
- **Фронт (vitest):** `buildRecurrence` (диапазон и N недель, набор дней, граничные дни),
  `buildWeekCopy` (сдвиг недели, пропуск отменённых), `buildDuplicate` (несколько дат),
  `findOverlappingIds` (группа 2+ в одном слоте; разное время не подсвечивается;
  отменённые не считаются).
- Тесты дата-функций — основная страховка корректности (вся логика повторов там).
